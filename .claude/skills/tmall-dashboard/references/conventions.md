## 统计口径

### 比率先汇总再相除

```
✓ 退款率 = Σ退款 ÷ ΣGMV
✗ 退款率 = avg(每日退款率)
```

后者等于给成交 3 万和 300 万的日子同样的权重。适用于所有 ROI、费比、转化率、客单价、UV 价值、占比。

推论：**模型里存绝对值，不存比率**。新客率在源表里是个百分比，解析时立刻乘回 GMV 存成 `newCustomerGmv` —— 比率要能跨区间加权汇总，只能靠绝对值。

### 率型目标按分母加权

合并多个月的率目标时，不能直接平均。`targetsForRange` 里每个率指标声明 `weightBy`（通常是 `gmv`），按分母目标加权：

```
总费比目标 = Σ(月费比 × 月GMV目标) ÷ Σ月GMV目标
```

### 达成度的基准分两种

| 指标类型 | 基准 | 理由 |
|---|---|---|
| 累加型（GMV、投放费、利润、搜索 UV） | **计划进度** | 8 月 6 号完成全月目标的 19% 是正常的，拿 100% 当基准会把每个月初都判成灾难 |
| 水平型（ROI、各种率） | **100%** | ROI 是个比值，不随时间累积；「ROI 达成 85%」就是没做到，和月初月末无关 |

代码里的判据是 `metric.weightBy ? 1 : (finished ? 1 : pace)`。

### 计划进度不是日历进度

「已过天数 ÷ 总天数」对电商是错的 —— 下半年的目标有很大一块压在 11 月的双 11 上，8 月初按日历算已经走了 20%，但按计划只该完成 16%，拿 20% 当基准会把一个正常的 8 月判成「落后」。

正确算法（`expectedProgress`）：按**月度 GMV 目标的分布**加权，即「区间起点到今天的目标和 ÷ 全周期目标和」。没有月度目标时才退回按天。

### 百分点 vs 百分比

率型指标的偏差用**百分点（pp）**，不用百分比。「退款率达成 108.7%」没人读得懂，运营要的是「超了 2.2 个点」—— 同一个事实，pp 是可加可比的单位，比值不是。

差不到 0.05 个点就当持平：摆一个带负号的零还染成绿色，等于把舍入误差说成了成绩。

## 图表规范

### 绝不用双轴

量纲不同的指标不塞进同一根真值轴。两条轴怎么对齐是任意的 —— 把其中一条上下挪一点，两条线就能"看起来相关"或"看起来无关"，这是凭空造出来的相关性。

需要多指标同图时：

1. **同量纲且量级相近（≤25 倍）** → 绝对值共轴
2. **否则** → 整张图换成指数（首日=100），副标题写明，tooltip 仍报真实值

指数化的基数取**第一个非零日**，首日恰好是 0 时用 0 当基数会让整条线变成 Infinity。

### 一张图占一行

并排时每张只有半个宽度，30 根柱子挤在一起看不出形状。

### 柱子的横向排布有两套

- **纯柱状图**：一格一根，柱心在格心，间距 `pw/n`
- **折线（含折线里的柱）**：首尾点压在绘图区边界上，间距 `pw/(n-1)`

两套差半格。悬停色带和命中判定必须用**这张图自己的**排布（`hookTip` 的 `geo.cx` / `geo.hit`），用错了色带和柱子会错开 —— 图中间对得上、越往两头偏得越多，最边上差将近一格。这个 bug 存在过。

### 未完整的时间单位要标出来

月度对比图里，当月那根柱子打斜纹 —— 读者一眼能看出这根不能和旁边直接比高低。文案里也写「MTD，不可与完整月直接比」。

### 排行榜的名称列固定宽度

名字左对齐、固定 320px，条形吃掉剩下的宽度。给条形封顶会在它和数值之间留一段空白，读起来像「条形到这里就没了」；名字右对齐则每行起点都不一样，扫一列名字得来回找行首。

## 颜色与文案

### 涨跌色表达好坏，箭头表达方向

GMV ▲ 绿、退款率 ▲ 红、投放费 ▲ 红。「▲ 红」读作「涨了，而且这是坏事」。由指标的 `higherIsBetter` 决定，不由方向决定。

### 悬停用压暗，不用加亮

加亮要么改颜色（就和图例对不上了），要么描边（在密集柱子上会糊成一片）。压暗保留所有原色，只是把注意力从别处收回来。全站统一压到 **0.34**。

### 圆心 / 标签的字号按视觉宽度算

「1356.7万元」和「1356.7wan」都是 9 个字符，但汉字是全角，实际宽度差一半。按 `length` 挑字号，中文串必然压到环上。系数：600 字重下等宽数字约 0.62em，汉字约 1.08em。

### 数字用等宽

`.tnum` / `font-variant-numeric: tabular-nums`。一列数字不等宽的话，扫下来每一行的小数点都在跳。

### 说明性文字能删就删

页面上每多一句解释，读者就少看一眼数字。出处、口径这类附注放页尾；警告（比如「这是演示数据」）钉在顶部 —— 那不是解释，是「别拿这些数开会」。

## 动效

**入场动效由 JS 在生成 SVG 时按需挂类**，不是靠 CSS 覆盖。不需要动效时（滚轮缩放中、用户开了减少动态）干脆不挂 —— 否则元素插进来就已经开始动了，再撤销只会看到一次抽搐。

**基点要统一。** 柱子的缩放基点在盒底（也就是坐标轴上），所以是「从轴上长出来」；环形切片的基点统一到圆心，入场和悬停共用一套 —— 各用各的基点会在动画交接那一帧跳一下。

**每一处都要过 `prefers-reduced-motion`。** 通常保留状态变化（压暗）、去掉位移和缩放。

**重放动画用 WAAPI（`element.animate()`）而不是加 CSS 类。** 重放一个 CSS 动画得先摘类、强制回流、再挂回去，而鼠标一划就是几十次。

**板块切换只做淡入，不做位移。** 位移让整屏内容在切换瞬间挪一下，比硬切还显得毛躁。

## 无数据怎么显示

显示「—」或「无数据」，**不显示 0%**。0% 是一个事实陈述（「这个月一单没成」），「—」是「我不知道」。把后者写成前者是在编数据。

同理：区间没有数据时图上写「所选区间没有数据」，而不是画一张全零的图。
